# BCM-300 확장: NR-10E 지원과 독립 상태/제어

BCM-300의 전원·온도·외출·예약 제어와 실내·온돌·온수 프리셋을 제공합니다. **2026-09-21, BCM-300W + 경동 NR-10E에서 사용자가 동작을 확인했다고 보고하여 v1.7.11 안정판으로 배포했습니다. v1.7.12부터 프리셋과 NR-10E 온수 단계를 기본 제공합니다.** 제조사 공식 배포나 인증을 의미하지 않으며, 다른 조절기/펌웨어로 검증 범위를 확대하지 않습니다. 명령과 온도 매핑은 동작 확인을 받은 v1.7.11b2와 동일하며, v1.7.12는 옵션 기본값을 변경합니다.

## 설치

1. HACS 사용자 지정 저장소에 `https://github.com/gm2945/sihas-canary`를 Integration 유형으로 등록합니다.
2. 안정판 `v1.7.13`을 다운로드합니다. 시험판 표시를 켤 필요가 없습니다. 원본과 같은 `sihas` 통합이므로 두 버전을 동시에 설치하지 않습니다. 수동 설치 시 폴더를 백업한 후 `custom_components/sihas` 전체를 덮어씁니다.
3. Home Assistant를 재시작합니다. 기존 BCM climate의 unique ID는 유지됩니다.
4. 별도 구성 없이 NR-10E 온수 단계와 climate 프리셋이 표시됩니다. 신규 설치 또는 옵션 키가 없는 기존 설치는 두 기능이 기본으로 켜집니다.
5. 기존에 명시적으로 OFF로 저장한 옵션은 유지됩니다. 필요한 경우 설정 → 기기 및 서비스 → SiHAS → BCM 구성에서 변경할 수 있습니다. 옵션 저장 후 통합이 다시 로드됩니다.
6. 실내/온돌을 선택한 뒤 목표 온도를 조절합니다. 온수를 선택하면 온도 다이얼 대신 별도 온수 단계 엔티티의 저온/중온/고온을 사용합니다. 실제 entity_id는 HA가 생성합니다.

이 포크의 기본 프로필은 경동 NR-10E입니다. 다른 조절기 사용자는 구성에서 NR-10E 옵션을 끄세요. 온수 단계 엔티티는 NR-10E 옵션이 켜진 경우에만 생성됩니다. 옵션 기본 활성화는 엔티티 노출만 바꾸며, 시작 시 보일러에 제어 명령을 보내지 않습니다.
되돌리려면 백업한 폴더를 복원하고 HA를 재시작합니다. 새로 생성된 엔티티는 복원 후 사용할 수 없게 됩니다.

## 매핑

주소는 0부터 시작하는 레지스터 인덱스입니다.

| 기능 | 레지스터 | 노출 및 제어 |
|---|---|---|
| 전원 | R0: 0/1 | 전원 switch + 기존 climate의 켜기/끄기. 전원만 제어 |
| 실내 설정온도 | R1 | 실내 운전에서만 climate 온도 설정, NR-10E 10–40 °C |
| 온돌 설정온도 | R2 | 온돌 운전에서만 climate 온도 설정, NR-10E 40–80 °C |
| 온수 단계 | R3: 0/1/2 | select: 저온/중온/고온. 사용자 확인 NR-10E 프로필 전용 |
| 운전모드 | R4 bit 0: 온수, bit 1: 난방, bit 2: 온돌 | 운전모드 select + climate 프리셋: 실내/온돌/온수. 옵션 OFF 시 select 미생성, climate 조회만 제공 |
| 외출 | R5: 0/1 | select: 재실/외출 |
| 예약 | R6: 0/1 | switch: 미실행/실행. 시간표 편집은 미지원 |
| 실내온도 | R8 / 10 | 실내온도 sensor. 실내/온수 운전에서 climate 현재 온도로 표시 |
| 온돌온도 | R9 | 온돌 운전에서 climate 현재 온도로 표시 |
| 연소 | R11: 0/1 | 별도 binary_sensor |
| 오류 | R12: 0 정상, 나머지 오류 | problem binary_sensor, 원시값 속성 제공 |
| 물 보충 | R13: 0 충분, 1 부족 | sensor. 미확인 값은 unknown, 원시값 유지. 수압 측정값이 아님 |
| 보일러 연결 | R14: 0 온라인, 1 오프라인 | connectivity binary_sensor. BCM과 보일러 사이 상태 |

온수 모드에서 숫자 0/1/2를 °C로 표시하지 않고, climate 온도 설정을 비활성화합니다. 서비스 직접 호출도 차단합니다. 실내온도 소수점은 보존합니다. NR-10E 프로필에서 범위 밖 온도는 거부합니다.

## NR-10E 프리셋 의미

사용자가 시하스 앱에서 확인한 운전 조합입니다. 온수는 세 운전 조합에서 모두 활성화됩니다. 저온/중온/고온 설정은 별도 온수 단계 엔티티를 사용합니다.

| 프리셋 | 온수 | 실내 난방 | 온돌 난방 |
|---|---|---|---|
| 온수 | ON | OFF | OFF |
| 실내 | ON | ON | OFF |
| 온돌 | ON | OFF | ON |

## 호환성과 한계

- 기존 climate unique ID `BCM-<MAC>`를 유지합니다. 새 엔티티는 접미사가 붙은 별도 unique ID를 사용합니다.
- **기존 자동화 변경 필요:** HVAC 모드는 `off`/`heat` 두 개이며 이제 전원만 제어합니다. `heat`가 예약 실행을 뜻하던 이전 동작은 제거했습니다. `auto`/`fan_only` 명령은 더 이상 지원하지 않습니다. 외출과 예약은 별도 select/switch 엔티티를 사용하세요.
- HA 표준 climate에는 `on` 모드가 없어 기본 화면에서는 전원 켜짐이 **난방**으로 표시됩니다. 실제 연소 중이라는 뜻은 아닙니다. `climate.turn_on`과 `climate.turn_off`도 사용할 수 있습니다.
- 프리셋 전환은 R4에서 난방 플래그와 실내/온돌 플래그만 바꾸며, 온수 선택 시 난방을 끄고 온수를 활성화합니다. 상위 비트, 난방 시 기존 온수 활성화 여부, 온수 시 이전 난방 유형을 보존합니다. 전원·설정온도·외출·예약을 함께 바꾸지 않습니다.
- 프리셋 명령 후 상태를 재조회하고 필요하면 1초 간격으로 3번 더 확인합니다. 원하는 모드가 확인되지 않으면 오류를 반환하며 기존 실제 상태를 표시합니다. R4 전환은 사용자 소유 BCM-300W/NR-10E에서 동작 확인을 받았습니다. 다른 펌웨어는 별도 확인이 필요합니다. 오류가 나면 시하스 앱으로 전환하고 진단 정보를 비교하세요.
- 난방세기 약/중/강과 물 상태의 추가 '이상' 코드는 미확인입니다. 추정값으로 엔티티를 만들지 않았습니다.
- 연소 ON은 온수 가열일 수도 있으므로 `hvac_action=heating`으로 단정하지 않습니다. 전원 OFF는 off, 연소 OFF는 idle, 연소 중은 hvac_action을 생략하고 별도 연소 센서를 사용합니다.
- 5초마다 한 번 공유 조회합니다. 제어는 최신 상태 조회 → 검증 → 쓰기 → 재조회 순서이며, 장치가 보고한 상태만 반영합니다. 장치 반영이 늦으면 다음 조회에 표시됩니다.
- 조회/쓰기 실패 시 사용 불가 처리하고 명령 오류를 반환합니다. BCM은 응답하지만 보일러가 오프라인이면 연결 센서는 OFF, 나머지 제어·상태는 사용 불가입니다.
- NR-10E 옵션을 끄면 온수 엔티티는 더 이상 제공되지 않습니다. HA 엔티티 레지스트리에 이전 항목이 남으면 사용 불가로 표시될 수 있습니다.

## 미확인 항목 조사

통합의 진단 다운로드에 최근 레지스터 64개와 프리셋 옵션 상태가 포함됩니다. 이름, IP, MAC은 포함하지 않습니다. 앱에서 운전모드 또는 난방세기를 하나씩 바꾼 후 5초 이상 기다려 각 진단 파일을 비교하면 후보 값을 확인할 수 있습니다. 진단 다운로드 자체는 제어 명령을 보내지 않습니다. R4 쓰기 지원은 조회값만으로 확정할 수 없습니다.

## v1.7.13: 전원과 운전모드 바로 조작

기존 climate, 예약, 외출 모드, 온수 단계 및 센서를 유지하며 같은 BCM 장치에 다음 두 항목을 추가합니다.

- **전원** (`switch`): ON/OFF. climate와 같은 R0를 제어하며 프리셋·온도·외출·예약은 유지합니다.
- **운전모드** (`select`): 실내 / 온돌 / 온수. climate 프리셋과 동일한 검증·명령·재조회 경로를 사용하며 전원을 함께 켜지 않습니다.

추가 항목은 기본 활성화됩니다. 기존에 프리셋 전환 옵션을 명시적으로 끈 경우 운전모드 select는 생성하지 않습니다. 앱이나 climate에서 변경한 상태도 공유 조회 후 두 항목에 반영됩니다. 시작 시 제어 명령은 보내지 않습니다. 실제 entity_id는 HA가 생성하며, unique ID 접미사는 각각 `-power`, `-operation_mode`입니다.

추가 엔티티는 모의 테스트로 검증했으며 이번 버전의 실기기 검증은 아직 하지 않았습니다. 기존 명령 경로는 앞서 사용자가 BCM-300W + NR-10E에서 동작을 확인했습니다.
