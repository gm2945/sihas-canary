# BCM-300 확장: NR-10E 지원과 독립 상태/제어

이 브랜치는 BCM-300의 확인된 레지스터만 제어합니다. 실제 보일러 통신은 이 개발 환경에서 검증하지 않았습니다.

## 설치

1. 기존 `custom_components/sihas` 폴더를 백업합니다.
2. 이 브랜치의 `custom_components/sihas` 폴더 전체를 HA의 같은 경로에 덮어씁니다. 원본과 같은 `sihas` 통합이므로 두 버전을 동시에 설치하지 않습니다.
3. Home Assistant를 재시작합니다. 기존 BCM climate의 unique ID는 유지됩니다.
4. 설정 → 기기 및 서비스 → SiHAS의 해당 BCM 항목 → 구성에서 **경동 NR-10E 온수 3단계 사용**을 켭니다. 옵션 저장 후 통합이 다시 로드됩니다.
5. 온수 단계, 외출 모드, 예약 및 상태 엔티티를 확인합니다. 실제 entity_id는 기존 등록 이름과 중복 여부에 따라 HA가 생성합니다.

다른 조절기 사용자는 NR-10E 옵션을 켜지 마세요. 옵션 기본값은 꺼짐이며, 온수 단계 엔티티는 옵션이 켜진 경우에만 생성됩니다.
되돌리려면 백업한 폴더를 복원하고 HA를 재시작합니다. 새로 생성된 엔티티는 복원 후 사용할 수 없게 됩니다.

## 매핑

주소는 0부터 시작하는 레지스터 인덱스입니다.

| 기능 | 레지스터 | 노출 및 제어 |
|---|---|---|
| 전원 | R0: 0/1 | 기존 climate의 켜기/끄기. 외출·예약을 함께 변경하지 않음 |
| 실내 설정온도 | R1 | 실내 운전에서만 climate 온도 설정, NR-10E 10–40 °C |
| 온돌 설정온도 | R2 | 온돌 운전에서만 climate 온도 설정, NR-10E 40–80 °C |
| 온수 단계 | R3: 0/1/2 | select: 저온/중온/고온. 사용자 확인 NR-10E 프로필 전용 |
| 운전모드 | R4 bit 0: 온수, bit 1: 난방, bit 2: 온돌 | climate `preset_mode` 속성에 실내/온돌/온수 표시. **읽기 전용**, 프리셋 선택 서비스 미지원 |
| 외출 | R5: 0/1 | select: 재실/외출 |
| 예약 | R6: 0/1 | switch: 미실행/실행. 시간표 편집은 미지원 |
| 실내온도 | R8 / 10 | 실내온도 sensor. 실내/온수 운전에서 climate 현재 온도로 표시 |
| 온돌온도 | R9 | 온돌 운전에서 climate 현재 온도로 표시 |
| 연소 | R11: 0/1 | 별도 binary_sensor |
| 오류 | R12: 0 정상, 나머지 오류 | problem binary_sensor, 원시값 속성 제공 |
| 물 보충 | R13: 0 충분, 1 부족 | sensor. 미확인 값은 unknown, 원시값 유지. 수압 측정값이 아님 |
| 보일러 연결 | R14: 0 온라인, 1 오프라인 | connectivity binary_sensor. BCM과 보일러 사이 상태 |

온수 모드에서 숫자 0/1/2를 °C로 표시하지 않고, climate 온도 설정을 비활성화합니다. 서비스 직접 호출도 차단합니다. 실내온도 소수점은 보존합니다. NR-10E 프로필에서 범위 밖 온도는 거부합니다.

## 호환성과 한계

- 기존 climate unique ID `BCM-<MAC>`를 유지합니다. 새 엔티티는 접미사가 붙은 별도 unique ID를 사용합니다.
- 기존 자동화 호환을 위해 upstream의 HVAC 모드 의미를 유지합니다: `auto`는 외출/예약 해제, `heat`는 예약 실행, `fan_only`는 외출. 이 명칭은 upstream의 관례이며 실제 팬 기능이 아닙니다. 새 자동화는 독립 외출/예약 엔티티를 사용하세요.
- 실내/온돌/온수 전환 명령은 공개 코드에서 검증되지 않았으므로 R4를 쓰지 않습니다. `preset_mode` 속성만 읽을 수 있고 HA 프리셋 선택 UI는 활성화되지 않습니다.
- 난방세기 약/중/강과 물 상태의 추가 '이상' 코드는 미확인입니다. 추정값으로 엔티티를 만들지 않았습니다.
- 연소 ON은 온수 가열일 수도 있으므로 `hvac_action=heating`으로 단정하지 않습니다. 전원 OFF는 off, 연소 OFF는 idle, 연소 중은 hvac_action을 생략하고 별도 연소 센서를 사용합니다.
- 5초마다 한 번 공유 조회합니다. 제어는 최신 상태 조회 → 검증 → 쓰기 → 재조회 순서이며, 장치가 보고한 상태만 반영합니다. 장치 반영이 늦으면 다음 조회에 표시됩니다.
- 조회/쓰기 실패 시 사용 불가 처리하고 명령 오류를 반환합니다. BCM은 응답하지만 보일러가 오프라인이면 연결 센서는 OFF, 나머지 제어·상태는 사용 불가입니다.
- NR-10E 옵션을 끄면 온수 엔티티는 더 이상 제공되지 않습니다. HA 엔티티 레지스트리에 이전 항목이 남으면 사용 불가로 표시될 수 있습니다.

## 미확인 항목 조사

통합의 진단 다운로드에 최근 레지스터 64개가 포함됩니다. 이름, IP, MAC은 포함하지 않습니다. 앱에서 난방세기만 한 단계씩 바꾼 후 5초 이상 기다려 각 진단 파일을 비교하면 후보 주소를 찾을 수 있습니다. 이는 조회만 하며 미확인 레지스터에 명령을 보내지 않습니다. R4 역시 앱의 전환 전후 조회값과 실제 쓰기 규격을 별도로 검증해야 합니다.
